# Правила коммитов

## Основные правила

1. **Все коммиты на русском языке**
2. **Кратко и понятно** - первая строка до 50 символов
3. **Понятно, но не длинно** - избегайте излишней детализации

## Формат сообщения коммита

```
Краткое описание (до 50 символов)

Подробное описание (если нужно):
- Что изменилось
- Почему это было изменено
- Какие проблемы решены
```

## Примеры хороших коммитов

✅ **Хорошо:**
```
Добавить модель Product для каталога товаров
```

```
Исправить валидацию email в форме регистрации
```

```
Обновить зависимости в requirements.txt
```

```
Добавить тесты для API эндпоинтов
```

```
Рефакторинг: вынести логику в отдельный сервис
```

❌ **Плохо:**
```
fix
```

```
обновления
```

```
Исправление бага который был найден вчера вечером когда я тестировал форму регистрации и заметил что валидация email не работает правильно потому что регулярное выражение было неправильным
```

## Типы изменений (опционально)

Можно использовать префиксы для категоризации:
- `Добавить:` - новая функциональность
- `Исправить:` - исправление багов
- `Обновить:` - обновление зависимостей или версий
- `Рефакторинг:` - улучшение кода без изменения функциональности
- `Удалить:` - удаление кода или файлов
- `Документация:` - изменения в документации

## Использование шаблона

Шаблон коммита настроен в `.gitmessage`. При создании коммита через `git commit` (без `-m`) будет открыт редактор с шаблоном.

Для быстрых коммитов можно использовать:
```bash
git commit -m "Краткое описание на русском"
```
